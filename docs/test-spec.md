# 営業日報システム テスト仕様書

> 更新日: 2026-11-12 / 状態: 初版(リマインドのケースを前営業日の判定に合わせる)
> 対象の設計書: [requirements.md](requirements.md)、[screens.md](screens.md)、[api.md](api.md)

## 1. 目的と範囲

設計書に定めた機能、権限、業務ルールが正しく実装されていることを確認する。

| テストの種類    | 内容                                            | 本書の対象                             |
| --------------- | ----------------------------------------------- | -------------------------------------- |
| 単体テスト      | 関数やクラス単位のテスト                        | 対象外(開発者が実装と合わせて作成する) |
| APIテスト       | API仕様書に対する入出力、権限、業務ルールの確認 | 4章                                    |
| 画面テスト(E2E) | ブラウザ操作による業務シナリオの確認            | 5章                                    |
| 非機能テスト    | スマートフォン対応、性能、セキュリティ、運用    | 6章                                    |

## 2. テスト環境

| 項目           | 内容                                                                                   |
| -------------- | -------------------------------------------------------------------------------------- |
| サーバー       | ローカル、CI、ステージングを使う。下表のとおり、テストの種類ごとに実行する環境を分ける |
| PCブラウザ     | Google Chrome、Microsoft Edgeの最新版                                                  |
| スマートフォン | iPhoneのSafari、AndroidのGoogle Chromeの最新版                                         |
| 日時           | 定期処理と日付のテストでは、サーバーの現在日時を変更できるようにする(ローカルとCIのみ) |

| テスト                             | 実行する環境               | 時期                                                                                                                                                                 |
| ---------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| APIテスト(4章)                     | ローカルとCI               | 開発中と、プッシュごと                                                                                                                                               |
| 画面テスト(5章)                    | ローカルとCI、ステージング | 開発中と、本番へのデプロイ前                                                                                                                                         |
| NFR-01〜03、NFR-07、NFR-09、NFR-10 | ローカル                   | 開発中                                                                                                                                                               |
| NFR-04〜05、NFR-13(性能)           | ステージング               | 運用開始前と、性能に影響する変更の後。テストデータを投入して測定する。Neon は本番と同じ設定(計算サイズ0.25CU、自動停止あり)にする                                    |
| NFR-11(バックアップの復元)         | ステージング               | 運用開始前。ステージングでバックアップの処理を手動で実行し、そのバックアップから一時的な Neon プロジェクトに復元して確認する。確認後は一時的なプロジェクトを削除する |
| NFR-06、NFR-08                     | ステージングと本番         | 運用開始前                                                                                                                                                           |
| NFR-12                             | 本番                       | 運用開始後、最初の数日間                                                                                                                                             |

- 運用開始後の変更は、ローカルとCIでテストした後、ステージングで画面テストを行い、本番の確認用URL(トラフィックを流さないリビジョン)で表示を確認してから切り替える
- ステージングと復元の確認には実データを使わない
